# Мониторинг: что живёт на сервере, а что здесь

Стек стоит в `/opt/monitoring` на проде: prometheus, alertmanager, grafana,
loki, promtail. **Живой `prometheus.yml` и `docker-compose*.yml` в этом
репозитории не версионируются** — они существуют только на сервере.

Это признанный долг, а не устройство. Ровно этот класс — конфигурация,
живущая только на диске прода — 10.08 стоил суток простоя ai-mr.ru: откат
авто-деплоя вернул серверный `nginx/conf.d/ai-crm.conf` версией из репозитория
и стёр правки, которых в репозитории не было. Здесь хранятся куски, которые
я добавлял сам, чтобы их можно было восстановить, если том потеряется.

## Внешняя проба доступности (05.09.2026)

Наблюдатель снаружи: самопроба не может записать собственную смерть — упавшее
приложение не отчитается о том, что упало. Поэтому Prometheus сам ходит по
адресам через blackbox-exporter.

- `blackbox/blackbox.yml` — модули пробы, монтируется в контейнер как
  `/etc/blackbox`;
- `prometheus/blackbox-job.yml` — задание сбора, вставлено в `scrape_configs`
  живого `prometheus.yml`;
- служба `blackbox-exporter` дописана в `/opt/monitoring/docker-compose.exporters.yml`.

Наблюдаются `https://ai-salex.ru/api/health`, `https://ai-salex.ru/login` и
`https://mcp.me-ai.ru/health`, раз в минуту.

Поднимать так, чтобы не пересоздать соседей (Prometheus и Alertmanager
обслуживают и соседний контур; пересоздание Postgres таким же образом уже
давало 502 — см. память проекта):

```bash
cd /opt/monitoring
docker compose -f docker-compose.yml -f docker-compose.exporters.yml \
  up -d --no-deps blackbox-exporter
curl -X POST http://localhost:9090/-/reload   # --web.enable-lifecycle включён
```

Перезапуск Prometheus для этого НЕ нужен и нежелателен: на нём висит
оповещение соседнего контура.

## Что осталось незакрытым

**Тревога не дойдёт до владельца, если упал CRM.** Единственный получатель
Alertmanager — вебхук `http://172.17.0.1:8780/api/ops/alert`, то есть бэкенд
самого CRM. Про недоступность CRM это сообщение уходит в CRM и умирает там.
Тот же довод, которым обоснована внешняя проба, применим и к пути доставки, и
там он не применён. Нужен канал, переживающий отказ наблюдаемого; Telegram из
РФ недоступен (`api.telegram.org` отваливается по таймауту), поэтому выбор
канала — решение владельца.

**Правило `EndpointDown` не добавлено.** `prometheus/alert.rules.yml` на
сервере принадлежит root и правился выкатом соседнего контура
(`alert.rules.yml.bak-pre-crm-*`) — это общая зона, и без рабочего канала
доставки правило дало бы видимость покрытия вместо покрытия.

**Хранение 30 дней, а не 90.** `--storage.tsdb.retention.time=30d` в аргументах
контейнера. Изменение требует перезапуска Prometheus, то есть паузы в
оповещении общего контура. Место не ограничение: на диске свободно 59 ГБ из
230 ГБ.
