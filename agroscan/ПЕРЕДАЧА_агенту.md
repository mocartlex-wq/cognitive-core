# Agroscan — передача в работу

Конвейер анализа зарастания сельхозучастков по данным дистанционного
зондирования: на входе КПТ Роскадастра, на выходе готовый комплект
документов для вовлечения земель в оборот — схема частей ЗУ, проверочная
карта, пояснительная записка, пять приложений и кадастровые обменные
форматы (DXF, MIF/MID, каталог координат, GeoJSON).

Код: репозиторий `mocartlex-wq/cognitive-core`, ветка
`claude/greeting-53c47u`, каталог `agroscan/`.

---

## 1. Запуск

```bash
cd agroscan
pip install -r requirements.txt          # numpy, scipy, scikit-image, shapely,
                                         # rasterio, pyproj, Pillow, PyYAML,
                                         # openpyxl, ezdxf

# подготовить участок из КПТ: границы, смежники, ЗОУИТ, лесничества,
# подложки, адрес и ориентир — и написать конфиг
python3 cli.py prepare data/kpt/58_17_0130701_2026-07-15_kpt11.xml 58:17:0130701:29

# полный расчёт и выпуск комплекта
python3 cli.py run parcels/58-17-0130701-29.yaml

# инструмент разметки для правообладателя (HTML со встроенными подложками)
python3 cli.py tool parcels/58-17-0130701-29.yaml

# пачкой по папке конфигов
python3 cli.py batch parcels/ --log batch_log.json

# кэш загруженных данных ДЗЗ
python3 cli.py cache [--clear]
```

Флаги `run`: `--no-sheets` (без PDF), `--no-formats` (без обменных
форматов), `--no-cache` (перекачать данные заново).

Прогон участка 2 га — около минуты, 140 га — две-три; повторный быстрее,
данные берутся из `cache/`.

## 2. Конфиг участка

`parcels/<КН с дефисами>.yaml` пишется командой `prepare`, правится руками:

```yaml
kn: "58:17:0130701:29"
egrn_ha: 2.1911                 # площадь по сведениям ЕГРН — контрольная
zone: msk58-2                   # местная система координат
place: "Пензенская область, Малосердобинский район, Старославкинский сельсовет"
ориентир: "с. Новое Славкино, примерно в 4,9 км, по направлению на юго-восток"
вид_работ: "анализ зарастания"  # попадает в имена файлов

rings:     ../data/<тег>/rings.json      # граница ЗУ из КПТ, [[[E,N],…],…]
meta:      ../data/<тег>/bgmeta.json     # кадр снимка {e0,e1,n0,n1,W,H,mpp}
image:     ../data/<тег>/bg_summer.jpg
zouit:     ../data/<тег>/zouit.npy       # растр ЗОУИТ
forest:    ../data/<тег>/forest.npy      # лесничества из КПТ
neighbors: ../data/<тег>/neighbors.json
# markup:  ../data/<тег>/markup.json     # разметка правообладателя, когда придёт

cover_all: true                 # части покрывают участок целиком
parts: {"1": "…", "2": "…", "3": "…", "4": "…"}
priority: ["3", "4", "1", "2"]  # старшая зона забирает пересечение
belts: {source: manual}         # manual | auto | both
```

## 4. Источники данных

Ключей не требует ни один, кроме опционального Google.

| Источник | Что даёт |
|---|---|
| ESRI World Imagery / Clarity | ортофото 0,7 и 0,36 м — подложка расчёта крон |
| ESRI Wayback | архив снимков, ~200 датированных срезов с 2014 г. |
| Sentinel-2 L2A (каталог Element84, COG на S3) | NDVI/NDRE/NDMI, маска качества SCL, сезонные композиты |
| Landsat через ESRI ImageServer | готовый NDVI всех поколений с 1977 г. — датировка выбытия |
| Canopy Height Map (Meta/WRI) | высота полога ~1 м — отделяет лесополосу от самосева |
| Copernicus DEM GLO-30 | рельеф: уклоны, сток, овраги, высотные подложки |
| Hansen GFC, ESA WorldCover | независимый контроль классификации покрова |
| SoilGrids v2.0 (ISRIC) | гумус, гранулометрия, pH, ЕКО, плотность, класс WRB |
| Почвенная карта РСФСР 1:2 500 000 (Фридланд, 1988) через soil-db.ru | тип почвы, порода, разрезы |
| OpenStreetMap через Overpass (4 зеркала) | ближайшие населённые пункты: название, расстояние, направление |
| Google Maps Platform | текущий снимок; **выключен**, включается ключом `AGROSCAN_GOOGLE_KEY`. Исторической съёмки Google наружу не отдаёт вообще |
| КПТ Роскадастра (локальный XML) | границы, смежники, ЗОУИТ, лесничества, адрес, ориентир |

Языковая модель в расчёте не участвует: все решения — пороги по индексам,
высоте полога и геометрии, числа воспроизводимы.

## 5. Методика в двух абзацах

Проективное покрытие крон считается в скользящем окне 25 м по ортофото;
пороги 10 / 30 / 60 % дают слабое, среднее и сильное зарастание — все три
идут в ЧЗУ/1, потому что раскорчёвке подлежит любая древесная
растительность. Спорные места уточняются по тому, чего на ортофото нет:
древесное влагосодержание (NDMI) и высота полога от 3 м относят участок к
зарастанию, а класс «открытая почва» ставится только при подтверждении по
NDVI. Ареалы мельче 0,30 га растворяются в окружающем классе.

Части разводятся по приоритету ЗОУИТ → лесополосы → древесная → залежь,
не накладываются, непокрытый остаток раздаётся по существу растра, нити
уже 3 м отдаются соседу. Лесничества из КПТ вычитаются из рабочей площади
до классификации — это чужая категория земель. Площади частей сводятся с
площадью ЕГРН методом наибольшего остатка, поэтому «Итого» в ведомости
совпадает с выпиской до метра.

## 6. Контроль качества

`qa.check` гоняется на каждом прогоне, отчёт ложится в `result.json` и
страницей в записку. Проверки: сумма частей равна площади ЕГРН; части не
накладываются друг на друга; части внутри границы ЕГРН; части не заходят
на лесничества; в координатах нет лишних точек; нет частей уже 3 м;
участок покрыт без зазоров; все части непустые. Допуски — нулевые или
1 м², то есть проверка ловит брак, а не подтверждает хорошее.

## 7. Подводные камни

- **JSONB и asyncpg** к этому конвейеру отношения не имеют — он автономный,
  без базы и сервера.
- **Растр в DXF — внешняя ссылка по имени файла.** Переименовали чертёж
  или потеряли `.jpg` — AutoCAD откроет лист с пустым полем. Отдавать
  только архивом `…_AutoCAD.zip`.
- **Чистка вершин.** Кольца частей чистятся от совпадающих и лежащих на
  прямой точек с допуском в микрон. Генерализовать сильнее нельзя:
  Дуглас–Пёкер с 5 мм резал соседние части по-разному и давал наложения
  0,15 м² и зазоры 1,5 м².
- **`export.normalize`** когда-то сравнивал первую и последнюю вершины
  через `np.allclose`; на координатах МСК (2,2 млн м) относительный допуск
  считал совпавшими точки в 22 м, и живая вершина пропадала. Сравнение
  теперь абсолютное — не возвращать как «оптимизацию».
- **Overpass** отвечает через раз: четыре зеркала в два круга, ответ
  кэшируется. Пустой ответ зеркала не принимается за «вокруг ничего нет» —
  региональные выгрузки (например `overpass.osm.ch`) отдают 200 и пустоту.
- **Направление на населённый пункт** на схеме считается от участка к селу,
  а в КПТ записано наоборот (от ориентира к участку) — румбы
  противоположны, это не ошибка, в записке оговорено.
- **`relief_*.npy`** появляются только после прогона с приложением
  «Рельеф»; без них в инструменте разметки нет высотных подложек.
- **Регресс 1173 идёт в `out/` намеренно** (полный прогон обновляет
  комплект), регресс :74 — во временную папку, чтобы не затирать
  выпущенные файлы урезанным прогоном.

за правообладателем, для этого открыт инструмент разметки; принятая
разметка кладётся в `data/<тег>/markup.json`, строка `markup:` в конфиге
раскомментируется, участок пересобирается — контуры становятся ЧЗУ/4.

## 9. Тесты

```bash
cd agroscan
for f in tests/test_*.py; do python3 $f; done
```

17 файлов: разбор КПТ, площади, имена файлов, санитарные проверки
геометрии (qa падает на испорченной), автопоиск полос, схема, записка,
почвы, карта Фридланда, источники ретроспективы, ближайший населённый
пункт, DXF и архив для AutoCAD, инструмент разметки, датировка, пачка, и
два регресса на 1173 и :74 против эталонов, выпущенных до конвейера.

Правило проекта: у каждой проверки должен быть обратный случай — тест,
который обязан упасть на плохих данных. Проверка, которая никогда не
падает, бесполезна.
