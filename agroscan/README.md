# agroscan

Анализ зарастания земель сельскохозяйственного назначения по данным ДЗЗ
и подготовка кадастровых схем частей земельного участка (ЧЗУ).

## Запуск

```bash
cd agroscan
python3 cli.py prepare data/kpt/58_24_0341802.xml 58:24:0341802:1173  # новый участок из КПТ
python3 cli.py run parcels/58-24-0341802-1173.yaml   # один участок
python3 cli.py batch parcels --log batch_log.json     # пачка
python3 cli.py new 58:24:0341802:1234                 # заготовка конфига
python3 cli.py cache                                  # что накоплено, --clear чистит
```

`cli.py` работает из любой директории; `python3 -m agroscan` — только из этой
папки, потому что в корне репозитория лежит каталог с тем же именем.

Один вызов проходит весь путь: граница из КПТ → карта высот полога →
композит Sentinel-2 → классификация зарастания → защитные лесные полосы →
разведение частей ЗУ → проверки → `out/<КН>/`.

На участке 141 га это ~3 минуты, из них 80 с — загрузка шести сцен Sentinel-2.
Повторный прогон берёт их из кэша: те же данные загружаются за 1,5 с вместо 83.
Ключ кэша — источник, охват и параметры запроса, поэтому смена охвата или
сезона данные перезагружает.

В пакетном режиме упавший участок не роняет очередь: ошибка идёт в журнал,
работа продолжается, в конце печатается таблица со статусом и площадями.

## Что откуда берётся

| данные | источник | зачем |
|---|---|---|
| высота полога, ~1 м | Meta/WRI Canopy Height (S3, COG) | защитные лесные полосы; древесная растительность |
| Sentinel-2 L2A | каталог Element84 (STAC) | NDVI/NDRE/NDMI — уточнение классов, актуальная дата |
| ортофото 0,6 м | ESRI World Imagery / Clarity | проективное покрытие крон |
| Landsat 2/5/7/8 с 1977 г. | архив ESRI ImageServer | датировка выбытия из оборота |
| Copernicus DEM GLO-30 | S3, COG | уклоны, линии стока, овраги |
| Hansen GFC, ESA WorldCover | S3 / GCS, COG | независимая проверка площади древесной |
| SoilGrids v2.0 (ISRIC), 250 м | REST API | гранулометрия, гумус, pH, ЕКО, плотность |
| SoilGrids, растровые слои 250 м | глобальные COG (`/vsicurl`) | карта гумуса, глины и pH поверх снимка |
| SoilGrids WRB classification | REST API | тип почвы по международной классификации |
| Почвенная карта РСФСР 1:2,5 млн (Фридланд) | soil-db.ru, контур под центром ЗУ | тип почвы по-русски, сопутствующие, порода |
| Полевые разрезы базы soil-db | точки в габарите + карточка разреза | проверка: есть ли рядом фактические данные |
| граница, ЗОУИТ, смежники | КПТ Роскадастра (XML) | геометрия, юридические зоны, местная СК |
| лесничества (код типа 15) | КПТ Роскадастра (XML) | чужая категория земель — части ЧЗУ туда не заходят |

Внешние данные читаются окном через `/vsicurl` — глобальные тайлы целиком
не качаются. Индекс тайлов полога кэшируется в `cache/`.

## Структура

```
agroscan/
  geo.py        местные СК (МСК-58 зоны 1-3 и произвольный proj4), сетка снимка,
                выборка растров — привязка ВСЕГДА из файла, не из запроса
  rings.py      растр → полигоны: Дуглас-Пейкер, векторизация, площади
  classify.py   кроны, проективное покрытие, классы зарастания
  belts.py      защитные лесные полосы по высоте полога
  zones.py      части ЗУ: смыкание, обрезка, приоритет, добор остатка, чистка нитей
  qa.py         проверки геометрии
  pipeline.py   конвейер
  sources/      canopy.py (высота полога), sentinel.py (Sentinel-2)
parcels/        конфигурации участков
tests/          регресс по выпущенным комплектам
```

## Конфигурация участка

`parcels/*.yaml` — кадастровый номер, площадь ЕГРН, зона МСК, пути к данным,
состав частей, приоритет разведения и пороги. Умолчания в `config.DEFAULTS`,
в конфиге переопределяется только нужное.

Приоритет частей задаёт, кто забирает пересечение: `["3","4","1","2"]` —
лесополоса, попавшая в ЗОУИТ, уходит в ЗОУИТ, потому что мероприятия там
не проводятся в любом случае.

## Проверки

`qa.check` прогоняется в конце каждого запуска и печатается таблицей:

| проверка | допуск |
|---|---|
| сумма частей = площадь ЕГРН | 0,01 % |
| части не накладываются | 0 м² |
| части внутри границы ЕГРН | 0 м² |
| нет частей уже 3 м | 0 шт |
| участок покрыт без зазоров | ≤ 1 м² |

Смысл проверки — падать. Если она не падает никогда, её нет.

## Подводные камни

- **Привязку растра берём только из файла.** ESRI ImageServer расширяет
  запрошенный bbox под соотношение сторон `size`; на 1173 это растянуло
  привязку в 1,6 раза и увело края на 600 м. Обнаружилось по несовпадению
  контура со снимком, стоило полного пересчёта.
- **Карта высот полога снята в 2018-2020 гг.** Для лесополос это неважно —
  они были взрослыми и тогда. Для датировки зарастания её использовать
  нельзя, там работает ряд Landsat/Sentinel.
- **Выбор лет в ряду решает ответ.** Шаг в два года однажды пропустил
  2010-й и сдвинул дату выбытия с 2011 на 2002; лист выглядел исправным.
  С 1999 года берётся каждый год, при разрыве дата подаётся интервалом.
- **Краевой пиксель источника врёт.** Landsat 30 м на границе контура
  смешивает зарастающую часть с соседней пашней и создаёт «пар» тонкой
  каймой. При расчёте долей краевая полоса исключается.
- **Не всякая зона из КПТ идёт в ЧЗУ/3.** Приаэродромные подзоны имеют тот
  же код 6, что и охранные зоны ЛЭП, но накрывают участок целиком и
  ограничивают высотное строительство, а не сельхозработы. Зоны, покрывающие
  95 % участка и больше, из ЧЗУ/3 исключаются; на 1173 после этого маска
  совпала с прежней, готовой вручную, пиксель в пиксель.
- **Clarity отвечает редиректом.** Тайлы уходят на wayback.maptiles;
  без `-L` подложка молча получается ровно серой.
- **Полевых разрезов рядом с участками нет.** Точки разрезов soil-db
  достаются тем же протоколом, карточка открыта анонимно, но ближайший
  разрез к 1173 — 48 км (серые лесные), того же типа почвы — 98 км;
  у :74 ближайший — 105 км. Координаты в базе округлены до 0,01° (±1 км).
  Поэтому в записку идёт одна строка о ближайших разрезах, а не их
  таблицы: выдавать разрез за характеристику участка нельзя.
- **Контур почвенной карты берётся у soil-db.ru разбором её же клиента.**
  Страница отдаёт csrf-токен и снимок Livewire-компонента, `loadFeatures`
  возвращает контуры в габарите обычным GeoJSON (узкий габарит — 2 секунды),
  `showFeatureData` — атрибуты. Это чужой клиентский протокол: он может
  смениться, поэтому осечка гасится, а поле `soil_map.индекс` в конфиге
  остаётся ручным переопределением с приоритетом над автоматикой.
- **Полоса узнаётся по ширине, а не только по вытянутости.** Вытянутость
  по осям эллипса ломается на Y- и Г-образных полосах (на :29 такая
  фигура давала 1,5 при пороге 3). Ширина считается как площадь,
  делённая на длину осевой линии: для полосы это её ширина, а куртина
  100 × 100 м честно выходит широкой. На 1173 покрытие осевых линий
  ручной разметки выросло с 81 до 84 %, точность 79 → 78 %.
- **Самосев — не защитное насаждение.** Если на ранних снимках ряда
  (1977, 1985) на месте нынешнего древостоя был пар, это самосев на
  выбывшей пашне: он идёт в ЧЗУ/1 под раскорчёвку, а не в ЧЗУ/4.
  Проверка печатается в записке с цифрами.
- **IoU — плохая метрика для лесополос.** Правообладатель обводит их с
  запасом и размечает не все, поэтому IoU занижен по построению. Меряем
  покрытие осевых линий и точность в зоне, где разметка велась.
- **Лесничество — не ЗОУИТ.** В КПТ это зона с кодом типа 15 (например,
  «Лопатинское лесничество», 58:00-15.12). Земли лесного фонда — чужая
  категория: их площадь вычитается из рабочей до классификации, а QA
  отдельно меряет пересечение частей с лесничеством. На 58:17:0130701:29
  границы соприкасаются, но наложения нет — 0 м².
- **Геометрию ЗОУИТ не дешифрируем.** Она берётся из КПТ; узкий язык
  охранной зоны, рассекающий лесополосу, — это факт выписки, а не артефакт.

## Что выдаёт конвейер

Имя каждого файла начинается с кадастрового номера и вида работ
(`вид_работ` в конфиге участка, по умолчанию «анализ зарастания»): файлы
уходят заказчику по одному, вне своей папки, и «Пояснительная_записка.pdf»
из разных комплектов иначе неразличимы.

```
out/<КН>/<КН>_<вид работ>_…
  …Схема_ЧЗУ.pdf               схема расположения частей (A4 альбомная, 400 dpi)
  …Проверочная_карта.pdf       контуры без заливки на двух подложках + врезка
  …Пояснительная_записка.pdf   ведомость, методика, почвенная характеристика
                               с обзорной картой и координатной сеткой,
                               отчёт проверок, допущения
  …Границы_частей.dxf          слои CHZU_1…n, Granica_ZU, вырезы — для CAD
  …Границы_частей.mif / .mid   то же для MapInfo
  …Границы_частей_с_растром.dxf  DXF R2000: те же слои + привязанный снимок
  …Границы_частей_с_растром.jpg/.jgw  подложка и её привязка (лежат рядом с DXF)
  …Каталог_координат.csv/.xlsx X, Y, длина линии, дирекционный угол, широта/долгота
  …Ведомость_площадей.csv      части, м², га, доля, число контуров
  …Границы_частей_msk.geojson  геометрия в местной СК
  …Границы_частей_wgs84.geojson  она же в WGS84 — для QGIS и обмена
  …Приложение_ИК.pdf           композиты CIR / сельхоз / SWIR с разбором признаков
  …Приложение_динамика.pdf     ряд NDVI 1977-…, год выбытия из оборота
  …Приложение_рельеф.pdf       уклоны, линии стока, овражно-балочные формы
  …Приложение_архив.pdf        снимки высокого разрешения по датам (ESRI Wayback),
                               ретроспектива вместо шкалы времени Google Планеты
  …Приложение_почвы.pdf        профиль по горизонтам, тип почвы из двух источников
                               с построчной сверкой, что делать после
                               раскорчёвки; вторая страница — карта гумуса, глины
                               и pH поверх снимка с точками опробования
  chzu<N>.json, result.json    контуры и полный отчёт расчёта
  relief.json, timeseries.json измерения рельефа и ряд по годам
  soil.json                    почвенный профиль, точки опробования и разброс
                               слоёв карты в границах участка
```

В AutoCAD чертёж открывается сразу с подложкой: снимок вставлен в
координатах местной СК, файлы `.jpg` и `.jgw` должны лежать рядом с DXF
(если растр отвязался — `IMAGEATTACH` подхватит привязку из `.jgw`).
Слой `Podlozhka` гасится одним щелчком, если нужна чистая геометрия.
Простой `…Границы_частей.dxf` остался в формате R12 — он читается всем,
но растра в R12 нет вовсе.

Координаты частей чистятся от вершин, которых в геометрии нет: совпавших
и лежащих на прямой. Обобщения контура при этом не происходит — вершина,
отстоящая от прямой хотя бы на миллиметр, остаётся (генерализация делается
осознанно, настройкой `export.simplify_m`).

Площади частей сводятся с площадью по сведениям ЕГРН методом наибольшего
остатка: сумма в ведомости в точности равна площади участка, а сдвиг части
не превышает пары метров. Если части покрывают участок не целиком, сведение
не выполняется и «Итого» подписывается как сумма частей.

## Ретроспектива высокого разрешения и Google

Историческая съёмка Google (шкала времени в Google Планете) наружу не
отдаётся ни одним интерфейсом: она живёт только в настольной Google Earth
Pro. Maps Platform отдаёт текущий снимок, Earth Engine — чужие спутники,
которые конвейер и так считает сам. Поэтому архив берётся из ESRI Wayback:
около двухсот датированных срезов World Imagery с 2014 года, без ключей.
Срезов много, но съёмка конкретного участка обновлялась считаные разы —
Версии просеиваются по одному тайлу, и в лист идут только те даты, где снимок
действительно менялся (на 1173 — 10 из 196).

Текущий снимок Google добавляется отдельной панелью, если владелец задал
свой ключ Maps Platform:

```bash
export AGROSCAN_GOOGLE_KEY=<ключ Google Maps Platform>   # или GOOGLE_MAPS_API_KEY
```

Без ключа лист собирается как обычно, а в отчёте и в логе появляется
строка о том, почему панели Google нет.

## Разметка лесополос вручную

Автопоиск лесополос отвечает не всегда: на 58:17:0130701:29 полог низкий
(медиана 0 м, выше 8 м только 9 % площади), сплошных рядов нет, и кандидатов
он не дал вовсе. Решение остаётся за правообладателем, поэтому инструмент
разметки собирается одной командой:

```bash
python3 cli.py tool parcels/58-17-0130701-29.yaml [--out файл.html]
```

Страница самодостаточна (подложки внутри как data-URI, вес меньше мегабайта),
её можно опубликовать артефактом и открыть по ссылке. Внутри — два снимка,
высота полога и NDVI как подложки, граница ЗУ, контуры частей из расчёта и
кандидаты автопоиска слоями, рисование колец и вырезов, черновик в браузере.
Готовая разметка уходит обратно кнопкой «Передать Claude» (страница
публикует квитанцию с координатами) либо выгружается файлом GeoJSON.

Принятая разметка кладётся в `data/<тег>/markup.json`, строка `markup:` в
конфиге включается, и при следующем прогоне обведённые контуры становятся
ЧЗУ/4: площади сводятся заново, каталог координат и обменные форматы
обновляются. Проверено на :29 — контур 0,12 га ушёл в ЧЗУ/4, ЧЗУ/1
уменьшилась до 2,07 га, сумма частей осталась равной площади ЕГРН.

## Ближайший населённый пункт на схеме

На схеме ЧЗУ рядом с участком стоит стрелка в сторону ближайшего села с
подписью «с. Новое Славкино — 4,8 км» и второй строкой «от участка на
северо-запад (азимут 300°)». Название и координаты пункта берутся из
OpenStreetMap (Overpass, узлы `place=city|town|village|hamlet`), направление
считается по местным координатам самого пункта, а не по азимуту на глаз.

**Румб на схеме противоположен румбу из выписки** — это не ошибка: в КПТ
направление записано от ориентира к участку («участок находится в 4,9 км по
направлению на юго-восток от ориентира»), на схеме — от участка к пункту.
В записке это сказано отдельной строкой, там же печатается измеренное
расстояние (до центра пункта) рядом с ориентиром из КПТ.

Источник опрашивается через несколько зеркал Overpass и кэшируется: не
ответило ни одно — лист собирается без подписи, причина пишется в лог.
Подпись двигается редактором раскладки наравне с кадастровым номером.

## Почвы: два источника рядом

Данные о почве рознятся, поэтому лист показывает оба источника построчно —
Почвенную карту РСФСР 1:2 500 000 (Фридланд и др., 1988, soil-db.ru) и
SoilGrids v2.0 (ISRIC, 250 м), — а отдельной строкой печатает результат
сверки: где они согласуются, а где расходятся и почему (гранулометрия
карты относится к почвообразующей породе, SoilGrids — к слою 0–5 см).

Каталог координат включает и вырезы: без них площадь по координатам
расходится с ведомостью (на 1173 ЧЗУ/3 давала 53,02 га вместо 41,65).
Обход колец нормализован — по часовой стрелке от самой северной точки,
поэтому каталог не переставляется между запусками и его можно сравнивать
с предыдущей версией.
